## GET /v1/url/{project}

Returns the canonical URL for a project's page on 01Resolved.

**Parameters:** `project` (path, required) — the project slug

```bash
curl -H "x-api-key: YOUR_KEY" \
  "https://api.01resolved.com/v1/url/solomon"
```

<Accordion title="Example Response">
```json
{
  "data": null
}
```
</Accordion>

<Note>
  This endpoint is live but currently returns `null` for all projects. It is intended to resolve the canonical 01Resolved URL for a given project slug.
</Note>

## GET /v1/project-overview

Returns top-level token metrics and project description.

**Parameters:** `slug` (required)

```bash
curl -H "x-api-key: YOUR_KEY" \
  "https://api.01resolved.com/v1/project-overview?slug=solomon"
```

<Accordion title="Example Response">
```json
{
  "data": {
    "baseMint": "SoLo9oxzLDpcq1dpqAgMwgce5WqkRDtNXK7EPnbmeta",
    "tokenSymbol": "SOLO",
    "tokenPrice": "0.5914",
    "tokenPriceUSDChange24h": "-7.15",
    "volumeChanged24h": "89493.68",
    "totalSupply": "25799970.42",
    "circulatingSupply": "11424310.94",
    "icoPrice": 0.8,
    "projectDescription": "Solomon is building a more composable dollar...",
    "projectSubDescription": "The composable dollar that always earns"
  }
}
```
</Accordion>

| Field | Description |
|-------|-------------|
| `tokenPrice` | Current USD price of the token |
| `tokenPriceUSDChange24h` | 24h price change %. Formula: `((price_now - price_24h_ago) / price_24h_ago) × 100` |
| `volumeChanged24h` | 24h volume **change** percentage (not raw volume). Formula: `((vol_24h - vol_prev_24h) / vol_prev_24h) × 100` |
| `totalSupply` | Total tokens in existence. Formula: `total minted - total burned` |
| `circulatingSupply` | Tokens in circulation excluding locked team allocations. Formula: `total supply - performance package tokens` |
| `icoPrice` | Token price at time of ICO |
| `projectSubDescription` | Short one-line tagline for the project |

**Parameters:** `slug` (required)

```json
    "tokenSymbol": "SOLO",
    "tokenPrice": "0.741050591747177600",
    "decimals": 6,
    "priceChange24h": { "pct": "5.000629587750912283", "deltaUsd": "0.03529235519501644471" },
    "priceChange7d": { "pct": "-19.765708283802723185", "deltaUsd": "-0.18255772571439251832" },
    "liquidity": { "usd": "4591038.4401311073783517214092", "poolCount": 3 },
    "volume24h": { "usd": "110399.775189682393", "changePct": "139.1231101646548" },
    "marketCap": { "usd": "7799028.0216813553480079183968", "circulatingSupply": "10524285.532643000000000000" },
    "fdv": { "usd": "19119064.5240207933444319132672", "totalSupply": "25799945.019872000000000000" },
    "icoReturn": { "pct": "-7.3686760316028", "icoPrice": "0.8" },
    "nav": {
      "usd": "5396726.63921106",
      "adjustedSupply": "8455340.842669298999280154",
      "navPerAdjustedShareUsd": "0.638262459152071838",
      "snapshotAt": "2026-10-16T05:00:17.407Z"
    },
    "discount": { "pct": "16.104367587537457607" }
  }
}
```
</Accordion>

| Field | Description |
|-------|-------------|
| `priceChange24h` / `priceChange7d` | Price change over 24 hours and 7 days, as a percentage and in USD |
| `liquidity.usd` / `liquidity.poolCount` | Combined liquidity across the token's pools, and how many pools |
| `volume24h.usd` / `volume24h.changePct` | Trading volume over the last 24 hours, and its change from the 24 hours before |
| `marketCap.usd` | Formula: `tokenPrice × marketCap.circulatingSupply` |
| `fdv.usd` | Fully diluted valuation. Formula: `tokenPrice × fdv.totalSupply` |
| `icoReturn.pct` | Return since the ICO. Formula: `(tokenPrice − icoPrice) ÷ icoPrice × 100` |
| `nav` | NAV, adjusted supply, and NAV/AS from the latest snapshot. See `/v1/dao/treasury/nav-as-breakdown` for the full breakdown |
| `discount.pct` | Premium or discount to NAV/AS in %. Formula: `(tokenPrice − nav.navPerAdjustedShareUsd) ÷ nav.navPerAdjustedShareUsd × 100` |

<Warning>
  Despite its name, a **positive** `discount.pct` means the token trades at a **premium** to NAV/AS. Negative means a discount.
</Warning>

## GET /v1/growth-feed

Returns a project's operating metrics, such as volume, transactions, and active users, as daily history. Powers the **Operating Performance** section of a project's Overview tab.

**Parameters:** `slug` (required), `from`, `to`

`from` and `to` are UTC dates (`YYYY-MM-DD`), both inclusive. `to` defaults to yesterday and `from` to 89 days before `to`. The maximum range is 366 days.

```bash
curl -H "x-api-key: YOUR_KEY" \
  "https://api.01resolved.com/v1/growth-feed?slug=laso-finance&from=2026-10-12&to=2026-10-14"
```

<Accordion title="Example Response">
```json
{
  "data": {
    "slug": "laso-finance",
    "status": "available",
    "asOf": "2026-10-16T05:56:24.007Z",
    "expectedObservationDate": "2026-10-14",
    "latestObservationDate": "2026-10-14",
    "sourceGeneratedAt": "2026-10-15T06:30:12.567Z",
    "range": { "from": "2026-10-12", "to": "2026-10-14" },
    "metrics": [
      {
        "metricId": "protocol_volume_usd",
        "unit": "USD",
        "semantics": "flow",
        "definition": "Settled economic notional that UTC day, counted once per economic event.",
        "latest": {
          "date": "2026-10-14",
          "value": "29014.92",
          "methodologyVersion": "1.0",
          "sourceGeneratedAt": "2026-10-15T06:30:12.567Z"
        },
        "freshness": "current",
        "observations": [
          { "date": "2026-10-12", "value": "12741.07", "methodologyVersion": "1.0", "sourceGeneratedAt": "2026-10-14T06:30:12.948Z" },
          { "date": "2026-10-13", "value": "30528.98", "methodologyVersion": "1.0", "sourceGeneratedAt": "2026-10-15T06:30:12.567Z" },
          { "date": "2026-10-14", "value": "29014.92", "methodologyVersion": "1.0", "sourceGeneratedAt": "2026-10-15T06:30:12.567Z" }
        ]
      }
    ]
  }
}
```
</Accordion>

**Which metrics a project reports.** Each project chooses the 2 to 4 metrics that best describe its growth, so the set differs from project to project. Every metric comes from one standard catalog, identified by `metricId`, so the same ID means the same thing on every project. Each value covers one completed UTC day (00:00 to 23:59 UTC).

| `metricId` | Category | Unit | Type |
|------------|----------|------|------|
| `new_users` | Acquisition | count | `flow` |
| `app_downloads` | Acquisition | count | `flow` |
| `total_users` | Adoption | count | `stock` |
| `daily_active_users` | Engagement | count | `interval_unique` |
| `transactions` | Activity | count | `flow` |
| `protocol_volume_usd` | Activity | USD | `flow` |
| `value_held_usd` | Capital | USD | `stock` |
| `net_inflows_usd` | Capital | USD | `flow` |
| `supplied_assets_usd` | Lending | USD | `stock` |
| `outstanding_borrows_usd` | Lending | USD | `stock` |
| `stablecoin_supply_usd` | Stablecoin | USD | `stock` |
| `stablecoin_mint_volume_usd` | Stablecoin | USD | `flow` |
| `stablecoin_redemption_volume_usd` | Stablecoin | USD | `flow` |
| `yield_earned_usd` | Value delivered | USD | `flow` |

The type, returned as `semantics`, says how a day's value is counted:

| `semantics` | Meaning | Can you add days together? |
|-------------|---------|----------------------------|
| `flow` | Activity during that UTC day | Yes. Summing daily values gives the total for a period |
| `stock` | The value at the end of that UTC day | No. Use the last day's value |
| `interval_unique` | Distinct users during that UTC day | No. The same user active on two days would be counted twice |

| Field | Description |
|-------|-------------|
| `status` | `available` (data is flowing), `no_observations` (connected, no data yet), or `no_source` (the project does not publish a Growth Feed) |
| `expectedObservationDate` | The most recent day whose data is due. Each day's data is due by 06:00 UTC the following day |
| `latestObservationDate` | The most recent day with data across all metrics |
| `metrics[].latest` | The most recent value, regardless of the `from` and `to` range |
| `metrics[].freshness` | `current` if the latest day arrived by the 06:00 UTC deadline, `stale` if it is late, `no_observations` if there is no data |
| `metrics[].observations` | Daily values, oldest first. Values are exact decimal strings |
| `observations[].methodologyVersion` | Version of the project's calculation method. Compare values across dates only when the version matches |

<Note>
  A value of `0` means the true value was zero. Days with no data are left out of `observations` rather than reported as zero, and gaps are not filled in.
</Note>

<Note>
  Only projects that publish a Growth Feed return data. Currently that is Laso and P2P (`laso-finance`, `p2p-protocol`). Every other project returns `status: "no_source"` and an empty `metrics` array.
</Note>

Returns onchain DAO configuration and governance parameters.

**Parameters:** `slug` (required)

```bash
curl -H "x-api-key: YOUR_KEY" \
  "https://api.01resolved.com/v1/dao/overview?slug=solomon"
```

<Accordion title="Example Response">
```json
{
  "data": {
    "name": "Solomon",
    "slug": "solomon",
    "publicKey": "DzYtzoNvPbyFCzwZA6cSm9eDEEmxEB9f8AGkJXUXgnSA",
    "quoteMint": "EPjFWdd5AufqSSqeM2qN1xzybapC8G4wEGGkZwyTDt1v",
    "baseMint": "SoLo9oxzLDpcq1dpqAgMwgce5WqkRDtNXK7EPnbmeta",
    "spendingLimit": "100000000000",
    "passedThresholdBps": "300",
    "baseToStake": "1500000000000",
    "twapStartDelaySeconds": "86400",
    "teamSponsoredPassThresholdBps": "-300",
    "version": "0.6",
    "proposalCount": 0
  }
}
```
</Accordion>

| Field | Description |
|-------|-------------|
| `publicKey` | Onchain DAO program address |
| `quoteMint` | Quote token mint used in decision markets (typically USDC) |
| `spendingLimit` | Monthly spend limit in raw token units. Divide by `10^6` for USDC value |
| `passedThresholdBps` | TWAP pass threshold in basis points (300 = 3%) |
| `baseToStake` | Governance tokens required to open a proposal. Divide by `10^6` |
| `twapStartDelaySeconds` | Seconds after market open before TWAP starts (86400 = 24 hours) |
| `teamSponsoredPassThresholdBps` | Pass threshold for team-sponsored proposals in basis points. Negative values lower the required pass edge |

## GET /v1/legal-entity

Returns the registered legal entities behind a project, with their legal names and jurisdictions. Complements `/v1/project-overview/legals`, which returns document links rather than entity records.

**Parameters:** `slug`, `type`

<Warning>
  Pass the project as `slug`. Without it, or with `project=` instead, this endpoint returns entities for **all** projects.
</Warning>

```bash
curl -H "x-api-key: YOUR_KEY" \
  "https://api.01resolved.com/v1/legal-entity?slug=metadao"
```

<Accordion title="Example Response">
```json
{
  "data": [
    {
      "id": 3,
      "project": "metadao",
      "type": "DAO",
      "legalName": "MetaDAO LLC",
      "entityName": "MetaDAO",
      "jurisdiction": "Marshall Islands"
    },
    {
      "id": 4,
      "project": "metadao",
      "type": "OpCo",
      "legalName": "Organization Technology LLC",
      "entityName": "MetaDAO OpCo",
      "jurisdiction": "Wyoming"
    }
  ]
}
```
</Accordion>

| Field | Description |
|-------|-------------|
| `type` | `DAO` or `OpCo`. Filterable via the `type` parameter |
| `legalName` | Registered legal name of the entity (e.g. `MetaDAO LLC`) |
| `entityName` | Display name used across 01Resolved (e.g. `MetaDAO`) |
| `jurisdiction` | Where the entity is incorporated (e.g. `Marshall Islands`, `Wyoming`) |

<Note>
  Not every project has recorded legal entities. Projects without them return an empty array. The `DAO` / `OpCo` split here matches the `entityType` field used throughout the movement and account endpoints.
</Note>
