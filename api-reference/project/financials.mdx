## GET /v1/dao/treasury/overview

Returns a project's headline treasury figures in one call: NAV, NAV/AS, premium or discount to NAV/AS, runway range, and the monthly allowance. Powers the **Treasury** cards on the Financials tab and the **Monthly Allowance** card on the Overview tab.

**Parameters:** `slug` (required)

```bash
curl -H "x-api-key: YOUR_KEY" \
  "https://api.01resolved.com/v1/dao/treasury/overview?slug=solomon"
```

<Accordion title="Example Response">
```json

    "nav": "5397852.87689693",
    "navPerAdjustedShare": "0.638322292456433533",
    "spotPremiumDiscountToNav": "16.180087616962251081",
    "monthlyAllowance": "100000.00000000",
    "monthsOfRunway": {
      "min": "23.794504255556556514",
      "max": "53.978528768969254418"
    },
    "allowance": {
      "status": "ok",
      "period": "month",
      "mint": "EPjFWdd5AufqSSqeM2qN1xzybapC8G4wEGGkZwyTDt1v",
      "tokenSymbol": "USDC",
      "amount": "100000",
      "drawn": "0",
      "remaining": "100000",
      "amountUsd": "100000",
      "drawnUsd": "0",
      "remainingUsd": "100000",
      "periodStart": "2026-10-14T19:30:24.000Z",
      "nextRenewalAt": "2026-11-13T19:30:24.000Z",
      "observedAt": "2026-10-16T07:15:16.428Z",
      "matchesIndexedLimit": true
    }
  }
}
```
</Accordion>

| Field | Description |
|-------|-------------|
| `nav` | NAV in USD: the treasury's non-native value. See `/v1/dao/treasury/nav-as-breakdown` for its components |
| `navPerAdjustedShare` | NAV per Adjusted Supply (NAV/AS). Formula: `(Treasury Stables + LP Value (non-native side) + Other Non-Native Holdings) ÷ (Total Supply − Protocol-Controlled Tokens − Unvested Allocations)`. If NAV/AS > spot price, the project is trading at a relative discount. If NAV/AS < spot price, it is trading at a relative premium. |
| `spotPremiumDiscountToNav` | Premium or discount of the spot price to NAV/AS in %. Positive = premium, negative = discount |
| `monthlyAllowance` | The DAO's monthly spending allowance in USD |
| `monthsOfRunway.min` | Runway excluding LP value. Formula: `non-native treasury ÷ monthlyAllowance` |
| `monthsOfRunway.max` | Runway including the non-native side of LP positions. See `/v1/dao/treasury/runway-breakdown` for the inputs |
| `allowance.drawn` / `allowance.remaining` | How much of this period's allowance has been spent and how much is left, in tokens. The `…Usd` fields give the same in USD |
| `allowance.periodStart` / `allowance.nextRenewalAt` | When the current allowance period started and when it next renews |
| `allowance.status` | State of the allowance, e.g. `ok` |

## GET /v1/dao/treasury

Returns every token the treasury holds, with amounts and prices.

**Parameters:** `slug` (required)

```bash
curl -H "x-api-key: YOUR_KEY" \
  "https://api.01resolved.com/v1/dao/treasury?slug=solomon"
```

<Accordion title="Example Response">
```json
{
  "data": {
    "totalAssetsValue": "5397465.890798684126736533187295813472386396749735",
    "groupedAssets": [
      {
        "tokenAddress": "USDvUSpnhCr9yBgj3UyVrD239HRUv4RsHwH2FxsWuMk",
        "amount": "3672802607541.71184735307634787333",
        "token": {
          "url": "https://coin-images.coingecko.com/coins/images/55255/large/USDv.png?1789197811",
          "symbol": "USDv",
          "decimals": 6,
          "usdPrice": "0.9998939257540795"
        }
      }
    ],
    "spendingLimit": "100000",
    "monthOfRunway": "3.00334123094"
  }
}
```
</Accordion>

| Field | Description |
|-------|-------------|
| `totalAssetsValue` | Total USD value across all tracked wallets |
| `groupedAssets[].tokenAddress` | The token's mint address. Holdings of the same token across wallets are combined |
| `groupedAssets[].amount` | Raw token amount. Divide by `10^decimals` for the human-readable value |
| `groupedAssets[].token.symbol` | Token ticker symbol |
| `groupedAssets[].token.decimals` | Token decimal places |
| `spendingLimit` | Monthly spend limit in USD |

<Note>Treasury value includes assets held in DAO wallets **and** LP positions. For runway, use `monthsOfRunway` in `/v1/dao/treasury/overview` or `/v1/dao/treasury/runway-breakdown`.</Note>

```bash
curl -H "x-api-key: YOUR_KEY" \
  "https://api.01resolved.com/v1/dao/treasury/chart?slug=solomon"
```

<Accordion title="Example Response">
```json
{
  "data": [
    { "timestamp": "2025-11-18T00:00:00.000Z", "value": "8000000" },
    { "timestamp": "2025-11-18T01:00:00.000Z", "value": "8000000" }
```

|-------|-------------|
| `timestamp` | UTC timestamp for this data point |

## GET /v1/dao/treasury/nav-as-breakdown

Returns everything behind a project's NAV per adjusted share (NAV/AS) from a single snapshot: the wallets that make up NAV, the assets left out of it, and the supply adjustments that turn total supply into adjusted supply. Powers the **NAV Breakdown** panel on the Financials tab.

**Parameters:** `slug` (required), `timestamp`

Pass `timestamp` (ISO 8601) to get the latest snapshot at or before that time. Omit it for the current snapshot.

```bash
curl -H "x-api-key: YOUR_KEY" \
  "https://api.01resolved.com/v1/dao/treasury/nav-as-breakdown?slug=solomon"
```

</Accordion>

| Field | Description |
|-------|-------------|
| `snapshotAt` | Time of the snapshot all figures come from |
| `netAssetValueUsd` | NAV in USD: the combined value of `treasuryWallets` |
| `navPerAdjustedShareUsd` | NAV/AS. Formula: `netAssetValueUsd ÷ adjustedSupply` |
| `treasuryWallets` | Wallets counted in NAV, each with its USD value and token holdings. For LP accounts (`isLpAccount: true`) only the non-native side is counted, shown as `daoOwnedAmount` and `daoOwnedValue` |
| `excludedFromNav` | Assets held but left out of NAV, mainly the project's own token sitting in LP pools and treasury wallets |
| `totalSupply.amount` | Total token supply |
| `supplyAdjustments` | Protocol-controlled and unvested balances subtracted from total supply |
| `adjustedSupply` | Supply used for NAV/AS. Formula: `totalSupply.amount − sum of supplyAdjustments` |

<Note>
  The project's own token never counts toward NAV, even when the treasury holds it. It appears in `excludedFromNav` instead, and the matching token balances are subtracted from supply in `supplyAdjustments`.
</Note>

## GET /v1/dao/treasury/runway-breakdown

Returns runway in months, calculated both with and without LP value, along with the inputs.

**Parameters:** `slug` (required), `timestamp`

```bash
curl -H "x-api-key: YOUR_KEY" \
  "https://api.01resolved.com/v1/dao/treasury/runway-breakdown?slug=solomon"
```

<Accordion title="Example Response">
```json
{
  "data": {
    "snapshotAt": "2026-10-16T05:00:17.407Z",
    "monthlySpendLimitUsd": "100000.00000000",
    "nonNativeTreasuryValueUsd": "2379218.98864854",
    "nonNativeLpValueUsd": "3017507.65056252",
    "runwayExcludingLpMonths": "23.792189886485403043",
    "runwayIncludingLpMonths": "53.967266392110581241"
  }
}
```
</Accordion>

| Field | Description |
|-------|-------------|
| `monthlySpendLimitUsd` | The DAO's monthly spend limit in USD |
| `nonNativeTreasuryValueUsd` | Treasury value excluding the project's own token and LP positions |
| `nonNativeLpValueUsd` | Non-native side of the treasury's LP positions |
| `runwayExcludingLpMonths` | Formula: `nonNativeTreasuryValueUsd ÷ monthlySpendLimitUsd` |
| `runwayIncludingLpMonths` | Formula: `(nonNativeTreasuryValueUsd + nonNativeLpValueUsd) ÷ monthlySpendLimitUsd` |

The two treasury inputs add up to NAV: `nonNativeTreasuryValueUsd + nonNativeLpValueUsd = netAssetValueUsd` in `/v1/dao/treasury/nav-as-breakdown`.

## GET /v1/dao/project-timeline

Returns the date range covered by 01Resolved's data for this DAO.

**Parameters:** `slug` (required)

```bash
curl -H "x-api-key: YOUR_KEY" \
  "https://api.01resolved.com/v1/dao/project-timeline?slug=metadao"
```

<Accordion title="Example Response">
```json
{
  "data": {
    "startTime": "2025-12-23T00:00:00.000Z",
    "endTime": "2026-06-02T00:00:00.000Z"
  }
}
```
</Accordion>

| Field | Description |
|-------|-------------|
| `startTime` | Earliest timestamp in 01Resolved's dataset for this project |
| `endTime` | Most recent timestamp in the dataset |
