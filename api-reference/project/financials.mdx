## GET /v1/dao/treasury/overview

Returns a project's headline treasury figures in one call: NAV, NAV/AS, premium or discount to NAV/AS, runway range, and the monthly allowance. Powers the **Treasury** cards on the Financials tab and the **Monthly Allowance** card on the Overview tab.

**Parameters:** `slug` (required)

```bash
curl -H "x-api-key: YOUR_KEY" \
  "https://api.01resolved.com/v1/dao/treasury/overview?slug=solomon"
```

| Field | Description |
|-------|-------------|
| `nav` | NAV in USD: the treasury's non-native value. See `/v1/dao/treasury/nav-as-breakdown` for its components |
| `navPerAdjustedSupplyUsd` | NAV per adjusted token in USD: `nav ÷ adjusted supply`. See the NAV/AS breakdown for configured supply exclusions |
| `premiumDiscountPct` | Premium or discount of spot price to NAV/AS, in percent. Positive = premium, negative = discount |
| `navPerAdjustedShare` | Deprecated alias of `navPerAdjustedSupplyUsd` |

| `monthlyAllowance` | The DAO's monthly spending allowance in USD |
| `monthsOfRunway.min` | Runway excluding LP value. Formula: `non-native treasury ÷ monthlyAllowance` |
| `monthsOfRunway.max` | Runway including the non-native side of LP positions. See `/v1/dao/treasury/runway-breakdown` for the inputs |
| `allowance.drawn` / `allowance.remaining` | How much of this period's allowance has been spent and how much is left, in tokens. The `…Usd` fields give the same in USD |
| `allowance.periodStart` / `allowance.nextRenewalAt` | When the current allowance period started and when it next renews |
| `allowance.status` | State of the allowance, e.g. `ok` |

## GET /v1/dao/treasury

Returns every token the treasury holds, with amounts and prices.

**Parameters:** `slug` (required)

```bash
curl -H "x-api-key: YOUR_KEY" \
  "https://api.01resolved.com/v1/dao/treasury?slug=solomon"
```

<Accordion title="Example Response">
```json
{
  "data": {
    "totalAssetsValue": "5397465.890798684126736533187295813472386396749735",
    "groupedAssets": [
      {
        "tokenAddress": "USDvUSpnhCr9yBgj3UyVrD239HRUv4RsHwH2FxsWuMk",
        "amount": "3672802607541.71184735307634787333",
        "token": {
          "url": "https://coin-images.coingecko.com/coins/images/55255/large/USDv.png?1789197811",
          "symbol": "USDv",
          "decimals": 6,
          "usdPrice": "0.9998939257540795"
        }
      }
    ],
    "spendingLimit": "100000",
    "monthOfRunway": "3.00334123094"
  }
}
```
</Accordion>

| Field | Description |
|-------|-------------|
| `totalAssetsValue` | Total USD value across all tracked wallets |
| `groupedAssets[].tokenAddress` | The token's mint address. Holdings of the same token across wallets are combined |
| `groupedAssets[].amount` | Raw token amount. Divide by `10^decimals` for the human-readable value |
| `groupedAssets[].token.symbol` | Token ticker symbol |
| `groupedAssets[].token.decimals` | Token decimal places |
| `spendingLimit` | Monthly spend limit in USD |

<Note>The asset inventory is not a substitute for the published NAV calculation. Use `nav-as-breakdown` for included assets and supply exclusions, and `runway-breakdown` for the spendable-treasury and LP runway inputs.</Note>


<Accordion title="Example Response">

## GET /v1/dao/treasury/nav-as-breakdown

Returns everything behind a project's NAV per adjusted share (NAV/AS) from a single snapshot: the wallets that make up NAV, the assets left out of it, and the supply adjustments that turn total supply into adjusted supply. Powers the **NAV Breakdown** panel on the Financials tab.

**Parameters:** `slug` (required), `timestamp`

Pass `timestamp` (ISO 8601) to get the latest snapshot at or before that time. Omit it for the current snapshot.

ISO dates (UTC midnight), ISO datetimes and Unix seconds are accepted. Check the returned `snapshotAt`; the selected snapshot may be earlier than the request. History limits still apply.

```bash
curl -H "x-api-key: YOUR_KEY" \
  "https://api.01resolved.com/v1/dao/treasury/nav-as-breakdown?slug=solomon"
```

| Field | Description |
|-------|-------------|
| `snapshotAt` | Time of the snapshot all figures come from |
| `netAssetValueUsd` | NAV in USD: the combined value of `treasuryWallets` |
| `navPerAdjustedSupplyUsd` | NAV/AS in USD. Formula: `netAssetValueUsd ÷ adjustedSupply` |
| `navPerAdjustedShareUsd` | Deprecated alias of `navPerAdjustedSupplyUsd` |

An item appearing in `excludedFromNav` does not by itself establish a supply exclusion; inspect `supplyAdjustments`. Pending LP fees are disclosure-only under the current default.
</Note>

## GET /v1/dao/treasury/breakdown

Returns the included and excluded treasury components together with the snapshot's methodology and data quality. Use this alongside `nav-as-breakdown` to investigate the source of a NAV figure.

**Parameters:** `slug` (required), `timestamp` (optional; latest eligible snapshot at or before this time)

```bash
curl -H "x-api-key: YOUR_KEY" \
  "https://api.01resolved.com/v1/dao/treasury/breakdown?slug=solomon&timestamp=2026-10-16T05:00:17.407Z"
```

| Field | Description |
|-------|-------------|
| `snapshotAt` | Actual timestamp of the selected published, non-spike snapshot |
| `netAssetValueUsd` | NAV numerator in USD |
| `dataQualityStatus` | Whether the saved snapshot is complete or degraded |
| `qualityFlags` | Saved warnings about inputs; an empty array is not a guarantee of complete historical coverage |
| `methodologyVersion`, `methodologyCode` | Methodology attached to this snapshot |
| `treasuryWallets`, `excludedFromNav` | Included and excluded component groups; SOL holdings may appear as a separate aggregate line |

## GET /v1/dao/treasury/nav-as-chart

Returns NAV/AS, token price, adjusted supply, treasury value and premium/discount from published, non-spike snapshots. Sending a date boundary selects hourly window mode; otherwise the request uses range mode.

| Parameter | Description |
|-----------|-------------|
| `slug` | Required project slug |
| `range` | `1D`, `1W`, `1M`, `3M` (default), or `ALL`; used when neither date boundary is supplied |
| `startDate` | Optional UTC ISO date/datetime; inclusive hourly window start |
| `endDate` | Optional UTC ISO date/datetime; exclusive hourly window end |

Account and API-plan gates apply. On the website, `1D`, `1W` and `1M` are the open ranges; longer ranges and hourly windows require a signed-in account. Pro history is limited to the last 92 days; Builder and higher plans can access the full available history. A date-window request is limited to 92 days regardless of plan. A Pro `ALL` request is narrowed to its allowed hourly window.

### Range mode

```bash
curl -H "x-api-key: YOUR_KEY" \
  "https://api.01resolved.com/v1/dao/treasury/nav-as-chart?slug=solomon&range=1M"
```

`1D` and `1W` use hourly buckets, `1M` uses four-hour buckets, and `3M` uses twelve-hour buckets. `ALL` uses twelve-hour buckets for histories up to 730 days, daily buckets up to 2,920 days, then weekly buckets. Each regular point uses its bucket's latest snapshot and is stamped with the bucket start; it is not an average.

The response contains `range`, `resolution`, `today`, `launchStatus`, `historical`, `historicalDpRange`, `decisionMarkets` and `projected`, plus an optional `launchReference`. Historical points contain `timestamp`, `navAs`, `tokenPrice`, `adjustedSupply`, `treasuryValueUsd`, `premiumDiscountPct` and the deprecated percentage alias `discountPremium`.

The all-time premium/discount high and low can be included as additional points at their actual snapshot time, with `extreme: "high"` or `"low"`. An extra extreme in the newest bucket is deferred until that bucket closes. `historicalDpRange` describes the full saved history, not just the selected chart range.

`launchReference` is an ICO price reference, not observed NAV. `projected` contains a separate three-month allowance illustration, not recorded history. See [Historical NAV](/guides/historical-nav#ico-references-and-projections).

### Hourly window mode

```bash
curl -H "x-api-key: YOUR_KEY" \
  "https://api.01resolved.com/v1/dao/treasury/nav-as-chart?slug=solomon&startDate=2026-10-01T00:00:00Z&endDate=2026-10-08T00:00:00Z"
```

The latest eligible snapshot per UTC hour is returned in `[startDate, endDate)`. Missing hours are omitted. If `endDate` is omitted, it defaults to the end of the current UTC hour; if `startDate` is omitted, the default is 92 days before the end, subject to plan limits. The start must precede the end.

| Field | Description |
|-------|-------------|
| `resolution` | `hour` |
| `window.startDate`, `window.endDate` | Effective request boundaries, end exclusive |
| `firstHour` | Earliest published, non-spike snapshot time for this project, or null; not a claim of continuous coverage |
| `previousWindow` | Earlier allowed window as `{ startDate, endDate }`, or null when no earlier allowed window remains |
| `historical[].timestamp` | UTC hour boundary |
| `historical[].snapshotAt` | Actual source snapshot time; use this for a matching breakdown request |
| `historical[].navAs` | Published NAV per adjusted token in USD |
| `historical[].treasuryValueUsd` | Saved NAV numerator in USD |
| `historical[].adjustedSupply` | Saved denominator in token units |
| `historical[].tokenPrice` | Saved spot price in USD, or null |
| `historical[].premiumDiscountPct` | Saved premium/discount in percent, or null |
| `historical[].origin` | `observed` or `reconstructed` |
| `historical[].restated` | Whether the selected record has a supersession link or restatement reason |
| `historical[].qualityFlags` | Saved warnings about inputs |

Unlike range mode, hourly window mode returns no launch reference, projections or decision-market overlays. An empty `historical` array means no eligible records in that window; it does not mean treasury value was zero.

## GET /v1/dao/treasury/runway-breakdown

Returns runway in months, calculated both with and without LP value, along with the inputs.

**Parameters:** `slug` (required), `timestamp`

```bash
curl -H "x-api-key: YOUR_KEY" \
  "https://api.01resolved.com/v1/dao/treasury/runway-breakdown?slug=solomon"
```

<Accordion title="Example Response">
```json
{
  "data": {
    "snapshotAt": "2026-10-16T05:00:17.407Z",
    "monthlySpendLimitUsd": "100000.00000000",
    "nonNativeTreasuryValueUsd": "2379218.98864854",
    "nonNativeLpValueUsd": "3017507.65056252",
    "runwayExcludingLpMonths": "23.792189886485403043",
    "runwayIncludingLpMonths": "53.967266392110581241"
  }
}
```
</Accordion>

| Field | Description |
|-------|-------------|
| `monthlySpendLimitUsd` | The DAO's monthly spend limit in USD |
| `nonNativeTreasuryValueUsd` | Treasury value excluding the project's own token and LP positions |
| `nonNativeLpValueUsd` | Non-native side of the treasury's LP positions |
| `runwayExcludingLpMonths` | Formula: `nonNativeTreasuryValueUsd ÷ monthlySpendLimitUsd` |
| `runwayIncludingLpMonths` | Formula: `(nonNativeTreasuryValueUsd + nonNativeLpValueUsd) ÷ monthlySpendLimitUsd` |

The two inputs cover the runway-eligible non-native treasury and LP assets. An explicitly opted-in manual offchain value can increase NAV while remaining outside both runway buckets, so these inputs need not sum to the full NAV numerator. Runway uses the spending allowance, not a forecast of actual spending.

**Parameters:** `slug` (required)

</Accordion>

|-------|-------------|
